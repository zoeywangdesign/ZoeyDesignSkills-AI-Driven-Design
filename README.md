## 01 · AI-Driven Design Principles

**File →** `ai-driven-design-principles.md`

A foundational framework covering the paradigm shift in AI product design —  
from system-centric to user-centric, across Input, Interaction, and Output layers.

### Core Structure

```
Paradigm Shift
  ↓
Three-Layer Interaction Framework
  ├─ Input     Natural language over keywords
  ├─ Interact  Visible AI thinking over black box
  └─ Output    Generative rules over preset results
  ↓
Intent Spectrum & Multi-Format Response
  ↓
Layered Response Architecture
  ├─ Foundation Layer  ·  Functional  (can it work?)
  ├─ Context Layer     ·  Usable      (does it fit?)
  └─ Experience Layer  ·  Desirable   (do I want it?)
  ↓
Core Methodology
  ├─ From certainty → to generating possibility
  ├─ Bidirectional adaptation: AI capability ⇄ UX
  ├─ Visibility & controllability balance
  └─ Progressive trust building
  ↓
Quick-Reference Principle Cards
Design Checklists (Input / Interaction / Output / Trust / Context)
```

### Key Principles at a Glance

| Layer | Principle |
|-------|-----------|
| **Input** | Intent over keywords · Guide over educate · Progressive over complete |
| **Interaction** | Visible over black box · Dialogue over command · Proactive over reactive |
| **Output** | Rules over results · Generate over template · Adapt over fix |
| **Trust** | Transparent over mysterious · Stable over surprising · Correctable over perfect |

## 02 · AI-Powered Search Design Skill

**File →** `ecommerce-ai-search-design-skill.md`

An applied skill card focused on AI-driven product search experience design —  
distilled from hands-on practice in AI search interaction.

### The Core Thesis

> Users are no longer satisfied with *finding results* —  
> they expect the system to **understand** them.

### What This Skill Covers

**`0` Paradigm Shift**
The three-axis breakdown of how AI rewrites the search loop:

```
Before  →  Keywords  ·  Mechanical ops  ·  Fixed shelf
After   →  Natural language  ·  Dynamic dialogue  ·  Generative response
```

---

**`1` Input Layer — Trigger Intent**

```
Search box  →  Intent Trigger

· Externalize AI preferences as visible, adjustable controls
· Questions are built on user cognition, not system questionnaires
· Each question evolves based on the previous answer
· Path can exceed what the user consciously planned
```

---

**`2` Interaction Layer — Build Certainty**

```
The value of visible AI thinking
may exceed the value of the output itself.

· Make the invisible AI visible:
  what it's doing + that it's doing it right
· Domain-specific thinking, not generic AI output
· Step-by-step translation turns wait time into trust
```

---

**`3` Output Layer — Build Rules, Not Results**

```
Designers no longer craft perfect results.
They create elegant possibility spaces.

· Structural markup + object mapping = combinatorial compatibility
· Text density & rhythm are design variables
  that inversely constrain AI generation
· Intent Spectrum → Multiple response formats:
```

| Intent | Format |
|--------|--------|
| Clear single goal | Single product card |
| Comparison needed | Multi-product card |
| Exploratory | Collapsed feed |
| Contextual / gift | Checklist card |
| Visual / fashion | Outfit styling card |

---

**`4` Layered Response Architecture**

```
┌─────────────────────────────────────────┐
│  Experience Layer  ·  Desirable         │
│  Capture emotion & purchase motivation  │
├─────────────────────────────────────────┤
│  Context Layer  ·  Usable               │
│  Match behavioral logic per scenario    │
│  · Vague intent → Precise decision      │
│  · Sensory-driven → Instant decision    │
├─────────────────────────────────────────┤
│  Foundation Layer  ·  Functional        │
│  Information accuracy as core target    │
└─────────────────────────────────────────┘
```

---

**`5` The Designer's Role Redefined**

| Before | Now |
|--------|-----|
| Preset all possible results | Define generative rules |
| Design the perfect page | Create an elegant possibility space |
| Control every state | Define constraint boundaries |
| Display known content | Derive unknown responses |

## The Through-Line

Both documents share a single underlying shift in design philosophy:

```
System-centric  ──────────────────→  User-centric

Displaying known results            Deriving unknown responses
Controlling every pixel             Defining constraint rules
Designing the output                Designing the system
```

> **Technology serves people — not the other way around.**
