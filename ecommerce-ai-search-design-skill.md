# AI-Driven Search Design Skill
### Design Skill Card for AI-Powered Product Search

> **Core Thesis**: Users are no longer satisfied with "finding results" — they expect the system to *understand* them.
> AI search experience design must shift from **passive response** to **proactive understanding**.
> Designers no longer craft perfect results — they **create elegant possibility spaces**.

---

## 0. Paradigm Shift: The Starting Point

Traditional search is a closed loop:

```
User compresses intent into keywords
  → System queries product database
    → Returns a fixed shelf layout
      → User manually filters and compares
```

This is a **system-centric** design paradigm — it demands that users adapt to system rules, rather than the system understanding human intent.

AI-powered search deconstructs this loop across three axes:

| Layer | Traditional Mode | AI-Driven Mode |
|-------|-----------------|----------------|
| **Input** | Keywords | Natural language |
| **Interaction** | Mechanical operations | Dynamic dialogue |
| **Output** | Fixed shelf | Generative response |

---

## 1. Input Layer: Trigger Intent, Not Keyword Filling

### Core Principle

The search entry point is not just an input box — it is an **intent trigger**.

The design goal is: retain the familiar traditional search form (reduce migration cost), while using the entire page as a **context-driven guide** that encourages users to express needs through **natural sentences and multi-modal input**.

### Design Considerations

**1. Externalize shopping preferences as adjustable design elements**

User needs are vague, dynamic, and highly personal. In the dynamic function area of the search entry, the system's internal AI preference capabilities should be made visible — letting users feel they can adjust how the system understands them, rather than hiding this inside an algorithmic black box.

**2. Frame questions based on user cognition — not a system questionnaire**

The essence of guided questioning is not to have users fill out a form. Instead:

> AI, drawing on its existing understanding of the user, reorganizes fragmented and vague needs into a **contextualizable question chain**.

This means the questions themselves are a demonstration of AI capability — the more precisely it asks, the more trust it earns.

**3. Questions must be evolutionary, not fixed**

Each question dynamically evolves based on the previous answer. The path can go beyond the trajectory the user had consciously planned. Not a fixed decision tree — a flowing conversation.

## 2. Interaction Layer: Build Certainty, Not Expose Algorithms

### Core Principle

When users face the randomness and uncertainty of AI-generated content, **explicit design** is needed to help users understand how the AI operates and build trust.

> The value of making AI thinking visible may exceed the value of the output itself.

### Design Considerations

**1. Make the invisible AI visible**

Not "exposing the algorithm" — but letting users perceive two things:
- **What the AI is doing** (process visibility)
- **That the AI is doing it right** (judgment credibility)

This is not just a principle for conversational interaction — it points to a larger challenge: **helping people understand how AI thinks**.

**2. Thinking content must reflect domain expertise, not generic AI output**

AI thinking visualization should not be a display of generic knowledge retrieval. It should embed the **decision logic of the specific domain**.

In a product search context, the thinking process should reflect:
- Dimensions used to analyze product attributes
- How the system interprets user shopping preferences
- References to domain-specific data such as user reviews

The goal is a **deep thinking process that matches the decision logic of this specific context** — not generalized AI text.

**3. Step-by-step translation — managing wait anxiety**

Present the thinking process in steps. Not a bare loading animation, but meaningful information delivery — each step tells the user "here's what I'm doing for you right now." This converts waiting time into trust accumulation.

## 3. Output Layer: Build Rules, Not Preset Results

### Core Principle

Generative AI responses are inherently non-deterministic. The design focus must shift from **presetting results** to **constructing rules and logic**.

> This is not an upgrade in design craft — it is a shift in design thinking:
> from *displaying the known* to *deriving the unknown*.

### Design Considerations

**1. Solve the combinatorial compatibility problem**

Designers cannot enumerate every possible combination of content objects. The solution is:

Combine the structural freedom of **markup formatting** (e.g., Markdown) with the **data-driven mapping of content objects** (e.g., product cards), ensuring that any combination of elements remains compatible — so every freely generated response is delivered gracefully to the user.

**2. Text density and interleaving rhythm are key design variables**

In a product-centric search experience, text is not the protagonist — but it cannot be absent. Designers must consciously control:

- The density and organization of text
- The rhythm of alternation between text and product cards

These decisions should be **defined as a foundational pattern that inversely constrains and governs AI generation behavior**.

**3. Map intent spectrum to multiple response formats**

Different user inputs represent different intents, forming a spectrum from vague and broad to specific and precise.

The system should offer multiple content formats, flexibly matching different intent characteristics:

| Intent Characteristic | Response Format |
|----------------------|----------------|
| Clear goal, single-item decision | Single product card |
| Multiple options, comparison needed | Multi-product card |
| Exploratory, broad scope | Collapsed feed |
| Contextual need, requires structuring | Checklist card |
| Visually driven, outfit decision | Outfit / styling card |

**4. Establish a bidirectional adaptation mechanism**

AI capabilities and user experience must adapt to each other: AI capabilities inform design decisions, while design rules inversely constrain AI generation.
The designer's job is to define this ruleset — not to fill in every possible result.

## 4. Layered Response Architecture: Functional → Usable → Desirable

The diversity of user intent demands an interaction design that builds a **dynamically adaptive response system**. Three progressive layers, each with a distinct focus:

```
┌──────────────────────────────────────────────────┐
│  Experience Layer  ·  Desirable                  │
│  Activate intrinsic motivation                   │
│  Capture emotion and purchase intent             │
│  Only viable once the two layers below stabilize │
├──────────────────────────────────────────────────┤
│  Context Layer  ·  Usable                        │
│  Understand behavioral patterns and decision     │
│  logic for specific contexts                     │
│  Differentiate design strategies accordingly     │
├──────────────────────────────────────────────────┤
│  Foundation Layer  ·  Functional                 │
│  Core goal: information accuracy                 │
│  Achieve generality — stable support for         │
│  all contextual variations above                 │
└──────────────────────────────────────────────────┘
```

### Design Differentiation in the Context Layer

The core task of the Context Layer is: identify the behavioral patterns and decision logic of a specific context, then apply targeted design strategies.

Two directions as examples:

**Direction A: Vague Context → Precise Decision**
When user intent is abstract (e.g., gift-giving), use a checklist structure + contextual labels to convert vague needs into an actionable recommendation path — enabling a leap from ambiguity to precision.

**Direction B: Sensory-Driven → Instant Decision**
When user decisions are primarily driven by visual or sensory experience (e.g., fashion and beauty), lead with visual content and deeply integrate product information with sensory experience — building an immediate "see it, buy it" decision chain.

## 5. The Designer's Role Redefined

| Before | Now |
|--------|-----|
| Preset all possible results | Define generative rules |
| Design the perfect page | Create an elegant possibility space |
| Control every state | Define constraint boundaries |
| Display known content | Derive unknown responses |

---

## 6. The Long-Term Design Challenge

> **Technology serves people — not the other way around.**

The core challenges ahead:
- How to capture users' emotional states and purchase motivations
- How to build AI models that respond to those signals
- How to establish adaptive mechanisms and design rules that evolve with them

This is not a one-time design deliverable — it is a continuously evolving system.
